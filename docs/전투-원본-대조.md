# 전투·애니메이션 원본 대조

대상: 제공된 APK의 `lib/arm64-v8a/libgame.so`. 아래 주소는 이 파일의 가상 주소이며 다른 빌드에서는 달라집니다. 실행하지 않고 심볼·명령어·상수·호출 관계를 정적으로 읽었습니다. 한국어 유닛 데이터는 별도 시점의 역사 자료입니다. 이것을 원작 전체와의 동일성 검증으로 해석하면 안 됩니다.

## 일반 공격

`BattleUnitStatus::calcAttack @0x111932c`에서 확인한 기본 경로:

```
max(0, (ATK - trunc(DEF / 3)) × 속성 × R + ATK / randomInt(25,32))
```

- 보통 R: 0.900~1.000, 치명타 R: 1.500~1.600, 0.001 간격의 양끝 포함 난수.
- 치명타는 보통 R에 추가 곱하는 방식이 아니라 R의 범위를 바꿉니다. 기본 확률 10%, 원본 확률 상한 100% (`getTotalCriticalPer @0x1101678`).
- `getElementRevise @0x111bf24`: 유리 1.5, 불리 0.5, 보통 1.0. 빛·어둠은 서로 1.5.
- 원작은 이후 추가 보정·정수화·최소 피해 처리를 합니다. 웹판은 지원하는 기본 경로에 최종 최소 1을 적용합니다. 원작의 전체 패시브·방어 무시·피해 상한·실드·아레나·추가 공격 분기는 구현하지 않았습니다.
- 필살기 공격력·부대 강화·리더 스킬 조합은 제한된 웹판 구현입니다. 위 식을 확인했다고 모든 필살기가 원본 수치와 같아진 것은 아닙니다.

## 타격·스파크·차례

한국어 원문 `damage frames`의 프레임 배열과 피해 분배를 24종 모두 유지합니다. 입력 시 행동과 게이지만 소비하고, 피해는 각 타격 시점에 처리합니다. 이후 차례는 타격·복귀·결정 수신이 끝난 뒤 진행합니다.

`DamageList::setDamage @0x103f17c`는 같은 피해 대상, 스파크 가능 플래그, 동일 `waitCount`를 비교해 양쪽 패킷에 스파크를 지정합니다 (`0x103f42c~0x103f47c`). 서로 다른 공격자라는 추가 조건은 찾지 못했습니다. 기본 배율은 `DamageData::update @0x103bb60`의 1.5입니다. 과거 웹판의 입력 간격 320ms 방식은 제거했습니다.

가드 기본 남는 피해는 50%이며 패시브·버프로 조정됩니다 (`setDamage @0x1102c18`, `0x1103f9c`). 방어 자체의 고정 게이지 보너스는 없습니다. `onGuard @0x113f9e0`의 전용 효과가 있을 때만 적용되는 경로와, `exitAction @0x1100c40`의 피격 후 게이지 효과를 확인하여 웹판의 고정 +2를 제거했습니다.

## 결정

- 전투 결정 하나는 내부 100, 표시 기준 1 (`addBattleCrystal @0x1134fa0`). 살아 있는 선택 가능 유닛 중 무작위. 방어 중이거나 게이지가 찬 동료도 대상에서 제외하지 않습니다 (`getActiveUnitForRandom @0x1c3cee4`, `isTargetSelect @0x111e498`).
- 하트는 살아 있고 다친 유닛 중 무작위, 모두 건강하면 전체 생존 유닛 중 무작위 (`getHeartCrystalTarget @0x10b85ec`).
- 기본 하트 회복은 `trunc(REC / randomFloat(3.000,4.200))`, 최소 1 (`getHeartCrystalRecover @0x111fd1c`).
- 드롭 마스터는 없습니다. 웹판은 타격별 drop check 수만 원문에서 가져오며, 35% 결정 검사 후 실패 시 6% 하트 검사, 비행 800ms를 사용합니다. 이 확률과 시간은 원작 확정값이 아닙니다.
- 일반 전투에서는 실제 도착 시점에 체력·게이지를 상한 내에서 한 번만 반영합니다. 스크립트 훈련은 동기식 계산 어댑터를 사용하므로 수치 표시와 비행의 세부 동기화는 일반 전투와 다릅니다.

## 프레임 재생

| 경로 | 원본 근거 | 구현 |
| --- | --- | --- |
| CGG·CGS 캐릭터 | AppDelegate `0x102f864`, 1/60 설정 `0x102fb20`; BaseScene draw `0xfff078`; EdgeAnime action `0xffaf48` | 60fps 논리 프레임, 부분 이미지 변환·뒤집기·가산 합성, 원문 유지 |
| CGS 0 지속 시간 | EdgeAnime의 draw당 카운터 1 증가·delay 비교 | 최소 1프레임 |
| SAM | Native IncAnimFrameNum `0xfee760`: 24×dt | 24fps, 구간, 객체 유지·삭제·추가, 행렬·RGBA 보간 |
| SAM 해석 | Raymond Lu SuperAnim SDK의 객체·중심 좌표 처리 | APK int16 헤더 변형 반영. 확인한 26개 SAM의 변환 일치 |
| UI 좌표 | GameScene setLayoutParam `0x1606904`: CSV 좌표 ×0.5 | 640 기준 화면으로 1회 비례 축소 |

화면 전환 전체가 항상 320ms라는 뜻은 아닙니다. 원작의 초기화·다운로드 대기는 미포함이며, 웹판은 이 작업 레이어 전환을 편성과 상세 페이지에 적용합니다. 줄어든 움직임 설정에서는 생략합니다.

## 길게 누르기 안내

`MissionBattleManager::onFlickNavi @0x107a824`는 안내 하나만 restart합니다. 기본 경로에서 BB 사용 가능이면 `BraveBurstSlideMotion`(내부에 Guard도 포함), 사용할 수 없으면 `GuardSlideMotion`입니다. 두 SAM을 동시에 그리던 웹판 중복을 제거했습니다. 선택한 SAM과 같은 이름의 Add.sam만 가산 합성으로 겹쳐 재생합니다.

`touchBegan @0x107a4d4`에서 시작하고 `setWaitFrame(10)` (`0x107ac74`) 후 표시합니다. 대기는 SAM24fps가 아닌 draw당 감소(`0xff571c`, `0xfff1c0`)이므로 60Hz 기준 약166.7ms입니다. 두 SAM의 진짜 앵커는 320,320이며(`SuperAnimNode::Init @0xfecf14`), 원본 위치 보정을 버튼 중심으로 환산하면 왼쪽 열에 +16px, BB 유효 y457.5/Guard y313.5입니다. 이 좌표와 원본 레이어 행렬을 유지하며 영문 글자만 한글 캔버스로 대체했습니다.

일반 BB 제스처는 시작점보다 native y가30 이상 감소하고 기본1초 이내일 때, 가드는 y가60 이상 증가할 때 선택됩니다 (`touchEnded @0x107b214`, `0x107b5dc`, `FUNC_BB_TIMER=1000`). 웹판은320 기준 좌표로 환산합니다. 손을 떼면 안내를 즉시 숨깁니다. 키보드 사용자는 동료 칸에서 스페이스로 같은 메뉴를 열고 버튼을 선택하거나 Esc로 닫을 수 있습니다.

## 아직 원본과 같다고 할 수 없는 값

공격 접근·복귀 거리와 시간(접근 10프레임), 결정 비행 궤적·800ms, 타격 이펙트, 필살기 이펙트, 실제 전투 배치 좌표, 적 AI·정확한 HP·공격력·보상·드롭률, 모든 버프와 상태 이상, 장비·SBB·UBB·아레나·친구 리더. CGS가 정확해도 이러한 주위 연출과 서버 마스터가 없으면 전투 전체가 동일해지는 것은 아닙니다.
